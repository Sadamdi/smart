## Ringkasan

Aplikasi Next.js di `apps/web`. Semua data datang dari API (`/api/v1`) lewat proxy `/backend`. Token akses dan penyegar disimpan di localStorage; pada 401 klien menyegarkan token satu kali lalu mengulang permintaan, dan bila gagal pengguna diarahkan ke `/masuk`.

## Alur kerja fitur

```mermaid
flowchart TD
  A[Buka halaman] --> B{Token ada?}
  B -- tidak --> L[/masuk]
  B -- ya --> C[GET /me]
  C -- 401 --> D[POST /auth/refresh]
  D -- gagal --> L
  D -- berhasil --> C
  C --> E[AppShell + halaman]
  E --> F[Kueri TanStack: memuat, kosong, galat dengan coba lagi]
```

Fallback:

```text
 Peramban          Next (proxy /backend)        Backend
   | GET /me ---------->|--------------------------->|
   |<------ 401 --------|<---------------------------|
   | POST /auth/refresh |--------------------------->|
   |<-- token baru -----|                            |
   | GET /me (ulang) -->|--------------------------->|
```

| --- | --- |

## Cara uji

1. Jalankan backend lokal, lalu `BACKEND_ORIGIN=http://localhost:8000 npm run dev` di `apps/web`.
2. Daftarkan akun uji lewat layar Daftar atau API; jadikan satu akun admin lewat prosedur basis data.
3. Jalur gagal: tanpa token (diarahkan ke `/masuk`), mahasiswa membuka `/admin`, kata sandi salah, chat saat layanan AI mati.
4. Otomatis: `npm test` (klien API dan penyegaran token, form masuk dan daftar, kartu beasiswa, chat, validasi admin, unggah).
